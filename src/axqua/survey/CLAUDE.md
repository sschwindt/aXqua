# The survey planner (`axqua/survey/`, `axqua survey`)

The user's order of 2026-11-14: before a field campaign, say where measurements are needed so that the calibration parameters of the case can be determined, and plan the day. Four kinds of survey, alone or together (`settings.KINDS`): `ground` (wading with an acoustic Doppler velocimeter such as the FlowTracker), `airborne` (surface velocity from drone video, evaluated with pXv), `kayak` (drifter velocimetry after Barker et al. 2018) and `temperature` (fixed loggers or a mobile probe). `planner.make_plan` writes the folder `axqua-case/calibration-validation/survey-plan/` (`planner.FOLDER`, through `cfg.calibration_path`): `survey-plan.gpkg`, per kind `survey-map-<kind>.png` and `.pdf` and `survey-factsheet-<kind>.odt`, `survey-plan.json` with every number and `survey-settings.json` with the assumptions. The plugin reaches all of it through `axqua survey info|init|conditions|plan <case> --json` (`surveycli.py`); the pure tests are `tests/test_survey.py` (kernels) and `tests/test_survey_planner.py` (a built channel written by `tests/survey_case.py`, no simulation program).

**The plan rests on a steady result**, the last frame of `r2d.slf` at the discharge expected on the survey day (`field.load_field`; x and y from `geometry.slf`, because a result stores them in single precision). Without a result nothing is planned, and the error says to run the steady simulation. Points keep 15 mesh nodes from the liquid boundaries (the user's rule of 2026-11-04, the same function the calibration uses).

**Parameters and rules** (`placement.py`). Every calibration parameter has a rule that says where it acts: `zone` (inside one roughness zone), `everywhere`, `shear`, `bends`, `banks`, `margins`. `case_needs` reads `calibration.parameters`; `guess_rule` assigns the rule from the name. **The roughness zones of the zone map are offered too, where the calibration does not name them** (`map_zones`, note `ZONE_NOTE`): a case without calibration parameters used to offer nothing, although its zone map is what the user asked the planner to read. They are ticked when the case declares no parameter at all and unticked otherwise. A sediment parameter gets `SEDIMENT_NOTE` (velocities and depths say little about it). Points are spread by farthest-point sampling over position, velocity and depth, and a point placed for one parameter serves every other parameter whose rule it fulfills.

**The walk** (`walk.py`) is a directed graph on a raster, because wading is not symmetric: with the current at one speed, against it by depth class and weighted by the cosine of the angle to the flow, on land at the land speed, and no step into water that cannot be waded (depth limit, and a velocity limit per depth class). The fastest way between two points upstream of each other therefore leaves the water, follows the bank and enters again. Ground outside the model counts as land. The order of the points is an asymmetric tour from the access point and back; with several surveyors it is cut into one run each, and the DGPS surveyor gets a path of their own. One rover serves at most three probes (`ground.surveyors_per_dgps`), so a fourth surveyor brings a second rover with its own path. **A point that cannot be waded to is not walked to**: the router would lead to the nearest water that can be waded and count time for a visit that does not happen. In the temperature plan such a point comes last, with "boat, or a line from the bank" and without walk and time.

**Heights count from the riverbed** (the user's rule): 0.6 h for one depth, 0.2 h and 0.8 h for two, 0.2 h, 0.6 h and 0.8 h for three; the thresholds between one, two and three depths are settings. Never write "below the surface" in a factsheet or a hint.

**The day** (`schedule.py`, `conditions.py`). Without a start time the day starts at 00:00 and every time reads as time since the start; a day holds 8 h by default and ends at sunset when the date is known. Daylight is computed (NOAA's equations), so it needs no network. The weather is Open-Meteo, the country of a position Nominatim, the nearest mobile mast Overpass, and for Switzerland the federal coverage model; every request goes through `conditions._get` with the user agent `aXqua (https://axqua.eu)` and nothing personal. **No test reaches the internet**: the test modules replace `_get` with a function that fails, and plans are made with `online=False`. Without a network the country comes from `outlines.py`, coarse Natural Earth outlines of the twelve countries the user named, written by `scripts/build_country_outlines.py` from the world map QGIS installs. The file is a `.py` module because the wheel ships no other data (`scripts/check_wheel.py`); do not edit it by hand. Within about 10 km of another outline (`BORDER`) the report calls the country a guess and names the neighbor: Munich was first answered as Austria by a nearest-outline rule. Where no coverage map can be queried, the report says that the surveyors should check the coverage and names the national map and the correction services (`COUNTRIES`).

**The factsheet is one A4 page** (`factsheet.py`), narrow margins, Arial 10 pt, written with the standard library (an `.odt` is a zip of XML; no odfpy). The sheet counts its own lines with the character widths of Arial and leaves out the least important content step by step until the page holds it: single steps of the timetable, then the timetable as one row per surveyor and day, then later hints, then all warnings but the first. A test converts factsheets with LibreOffice where it is installed and counts the pages; Arial is not installed on the main workstation, where Liberation Sans, which has the same widths, takes its place.

**`survey-plan.gpkg`** (`output.py`) always holds the same layers (`LAYERS`). `access_points` belongs to the user (roles `access`, `leave`, `takeoff`, read forgivingly by `role_of`; an empty role is an access point, and a role that is none of the three is named in the notes and not used): aXqua creates it empty and never writes into it again. Every other layer is replaced by every plan, and the layers of a kind that is not planned are empty. Clean Up never offers the folder.

**Two snapshots keep the plugin and the library together**, because the plugin never imports `axqua`: `qgis_plugin/tests/survey_defaults.json` is `SurveySettings().as_dict()` (a test here fails when a default changes, and the plugin tests check that the forms hold exactly these settings), and a plugin test reads `settings.py` and `output.py` with `ast` to compare the kinds, their titles, the rules, the roles and the layer names. After a change of the settings write the file again: `json.dumps(SurveySettings().as_dict(), indent=2, sort_keys=True)`.

**Not done:** the German and French pages of the section (written by `deploy.sh`), a screenshot of the window in the docs, and a plan from an OpenFOAM result (the planner reads the TELEMAC result of the 2D model).
