# Post-processing with VisIt (`axqua/postproc/`)

Figures from either solver's results. VisIt ships **its own Python**, so aXqua generates a script and runs `visit -cli -nowin -s` - the same shape as sourcing an `etc/bashrc`. Installed at `/home/IWS/public/visit` (3.5.0, the `linux-x86_64-debian12` prebuilt); config block `postproc:` (`visit` names the **launcher executable**, not a script to source). CLI: `axqua postproc <config> [--list] [--script-only] [--scene ...]`, plus a per-case `postprocessing.py`.

**The seam is `SolverBackend.describe_results(cfg) -> list[Dataset]`** (`BaseBackend` returns `[]`): a backend *describes* what it produced - path, times, fields, patches - and `postproc` draws it. That is what keeps `postproc` from importing a solver, enforced by a test. It is a top-level package, not `core/`, because it renders matplotlib and `test_capabilities` requires a capability listing to import nothing heavy.

v1 scenes: **`free-surface`** (isosurface of `alpha.water=0.5`; under a rigid lid it falls back to the lid patch and **says on the figure that the surface was prescribed**), **`velocity-plan`** (slice at 0.6*h, the depth a FlowTracker measures at), **`profiles`** (bed-to-surface `Lineout` per vertical, exported as curves; **VisIt samples, matplotlib draws** - the measured overlay needs error bars and the comparison must stay reproducible without VisIt). Run `profiles` at the prior centre and at the posterior - those two panels are the calibration result.

**Three things found only by running it**, each pinned by a test: VisIt opens an OpenFOAM case through **`system/controlDict`**, not `case.foam` (unlike ParaView it rejects a zero-byte `.foam` - 0 meshes, 0 variables on VisIt 3.5.0), and its variables are mesh-prefixed (`internalMesh/U`); **the time slider must be set explicitly**, or the figure renders `t=0` (velocity identically zero) behind a `0.000` colour bar while looking well-formed; and the script **must end with `exit(0)`** or `-nowin` hangs forever.
