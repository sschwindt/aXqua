Batch-processing (visuelle Automatisierung)

Eine vollständige Studie besteht aus mehreren Schritten, die voneinander abhängen, zum Beispiel Preprocessing, einem Trockenlauf, einem Netzkonvergenzstudie und einer Kalibrierung. Batch-processing läuft eine solche Sequenz ohne Aufsicht.

Eine Abfolge von Schritten

Die Registerkarte Batch-processing listet die Schritte des Workflows für den aktiven Fall auf: den Build des TELEMAC-Modells, die stetige 2D-Simulation, die Netzkonvergenzstudie, den Build und den Lauf des 3D-Modells, den Build und den Lauf der Feinsediment-Simulation, die Bayessche Kalibrierung und die Validierung. Klicken Sie auf die auszuführenden Schritte und klicken Sie auf Submit the ticked steps. aXqua sendet einen Job pro Schritt in der Reihenfolge der Liste. Die Jobs dieser Schritte laufen einer nach dem anderen für einen Fall, so dass jeder Schritt beginnt, wenn der Schritt vorher beendet ist. Die Jobliste unter den Registerkarten zeigt waiting for mit der ID des Jobs, auf den ein Schritt wartet.

Ein Warteschritt prüft nicht, ob der Schritt vorher gelungen ist. Wenn der Build fehlschlägt, startet die folgende Simulation trotzdem und schlägt mit einer Nachricht fehl, die angibt, was fehlt. Verwenden Sie das unten beschriebene Skript für eine Sequenz, die beim ersten fehlgeschlagenen Schritt gestoppt werden muss.

Generieren Sie Batch-Verarbeitungsskript. Die Schaltfläche Generate batch-processing script… schreibt ein Shell-Skript für die angekreuzten Schritte und den aktiven Fall. Das Skript sendet die Schritte einzeln, wartet auf jeden Job und stoppt, wenn ein Job nicht abgeschlossen ist. Starten Sie es in einem Terminal mit nohup bash <script> &, so dass es weitergeht, nachdem Terminal geschlossen wurde (Batch-processing (Kopflos)).

Detach: Jobs gehen ohne QGIS weiter

Jede Simulation, die aus dem Plugin gestartet wird, ist ein Job, der beim Absenden von QGIS losgelöst wird. QGIS kann danach geschlossen werden, und der Computer kann für andere Arbeiten verwendet werden. Wenn QGIS wieder geöffnet wird, zeigt die Jobliste alle Jobs mit ihrem aktuellen Status an, einschließlich Jobs, die in der Zwischenzeit beendet oder fehlgeschlagen sind. Ein Job, der durch einen Neustart des Computers unterbrochen wurde, wird als fehlgeschlagen markiert und kann erneut eingereicht werden. Der Abschnitt Detach des Tabs gibt an, wo Jobs gehalten werden und wie sie losgelöst werden. Beide sind im Profil dieses Computers (Plugin Setup) eingestellt.

Sequenzen mit dem QGIS Model Designer

aXqua fügt dem QGIS Processing Toolbox drei Algorithmen hinzu, die im Modelldesigner von QGIS kombiniert werden können (Menü Processing):

Algorithmus

Funktion

Submit a simulation job

Prüft den Fall, erstellt einen Job und gibt seine ID zurück. Der Algorithmus wartet nicht auf die Simulation.

Check job status

Gibt den aktuellen Zustand und Fortschritt eines Jobs zurück.

Import job results

Laden Sie die Ergebnisse eines abgeschlossenen Auftrags mit den vordefinierten Kartenstilen.

Mit diesen Algorithmen kann der gleiche Fall beispielsweise für eine Reihe von Abflüssen eingereicht werden.
