Simulationssoftware

aXqua bereitet und startet Simulationen, aber die numerischen Codes sind separate Software, die zusätzlich installiert werden muss. Das Plugin hat ein Setup Wizard für TELEMAC und eins für OpenFOAM, das entweder ein bestehendes Installation in das Profil des Computers eingibt oder das Programm installiert. Zuerst TELEMAC einrichten. OpenFOAM (einschließlich Postprozessoren) ist optional und baut auf TELEMAC auf.

Bemerkung

Unter Windows laufen QGIS, das Plugin und das aXqua-Programm unter Windows. TELEMAC kann auf zwei Arten ausgeführt werden: im Windows-Subsystem für Linux (WSL 2), das in dieser Notiz beschrieben wird, oder als Windows-Programm, das in Ihrem Benutzerordner eingebaut ist und keinen Administrator und keine WSL benötigt, aber nur auf einem Prozessorkern läuft (TELEMAC basiert auf Windows). OpenFOAM läuft nur innerhalb von WSL.

Ein Administrator des Computers richtet WSL einmal ein: wsl --install -d Ubuntu-24.04 in einem Terminal mit Administratorrechten, dann einen Neustart; dann öffnen Sie Ubuntu aus dem Startmenü und erstellen Sie einen Linux-Benutzer. Nichts nach diesem Schritt braucht einen Administrator:

  • Der Setup Wizard installiert TELEMAC und OpenFOAM in der Standardverteilung in einem Ordner des Linux-Dateisystems (ein Build in einem Windows-Ordner wie /mnt/c/... ist um eine Größenordnung langsamer). Fehlende Systempakete werden als Stamm der Distribution installiert, die kein Passwort und keinen Administrator von Windows benötigt. Am Ende gibt der Assistent das Installation in das Profil des Computers als Installation in WSL ein.

  • Um ein bestehendes Installation zu verwenden, öffnen Sie Linux im Dateidialog von Select existing config file (den Ordner \\wsl.localhost), dann die Distribution und wählen Sie dort das Umgebungsskript aus.

  • ParaView und VisIt sind Windows-Programme unter Windows: Installieren Sie sie von ihren Websites (der ZIP von ParaView benötigt keinen Administrator) und geben Sie sie in das Profil ein.

  • Die Bayes-Kalibrierung mit HydroBayesCal ist unter Windows mit TELEMAC in WSL noch nicht verfügbar; Aufbau, Ausführung und Validierung eines Falls sind.

Diese Route wurde mit einem Stand-in nur für WSL getestet, noch nicht auf einem echten Windows Installation mit WSL.

Installationsassistenten (Kurzfassung)

Die Assistenten werden auf der Configuration Registerkarte geöffnet, in der Box Simulation & postprocessing software zeigt das Betriebssystem, das die aXqua Check Schaltfläche erkannt hat. TELEMAC und OpenFOAM haben jeweils die Schaltfläche Setup Wizard… und ParaView und VisIt die Schaltfläche Install ParaView and VisIt… (Postprozessoren).

Bemerkung

Wenn das aXqua-Programm Check vorhandene TELEMAC-, OpenFOAM- oder Postprozessor-Software Installation identifiziert hat, wird in der Box für jedes Programm angegeben, wo es installiert ist oder dass es nicht gefunden wurde.

Die erste Registerkarte von Setup Wizard, Setup fragt, wie aXqua das Programm finden kann:

  • Select existing config file ist die Wahl für ein Programm, das bereits auf diesem Computer installiert ist. Next öffnet die Registerkarte Existing installation, die angibt, welche Datei ausgewählt werden soll: das Umgebungsskript des Installation, das alle Variablen festlegt, die das Programm benötigt (TELEMAC: bestehende TELEMAC; OpenFOAM: bestehende OpenFOAM). Wählen Sie es mit Browse… und aXqua prüft, ob Installation für aXqua verwendbar ist. Use this installation gibt das Skript und den Installationsordner in das Profil ein (Plugin-Profil).

  • Install <Software-name> ist die Wahl für einen Computer ohne Programm. Die Schaltfläche Next liest Install <software-name>… und öffnet den Installationsassistenten.

Die Überprüfung eines vorhandenen Installation lädt das Umgebungsskript einmal und sucht nach jedem Teil des Installation, den aXqua verwendet. Es antwortet mit einem von drei Urteilen und listet jeden Teil als found (dunkelgrün) oder missing (fett dunkellila) mit dem auf, wofür er benötigt wird:

  • … was found and the installation is valid and complete.

  • … was found and the installation is valid, but some aXqua modules will not work: Das Programm läuft, und die Liste benennt die aXqua-Module, denen ein Teil fehlt, zum Beispiel die Morphodynamik ohne GAIA in TELEMAC oder die Feinsediment-Simulation ohne Olsens sediDriftFoam2 in OpenFOAM. Alles andere funktioniert, und das Installation kann in das Profil eingegeben werden.

  • This is not a usable installation of …: das Skript das Programm nicht einrichtet oder ein Teil, den jede Simulation benötigt, fehlt. Use this installation bleibt deaktiviert.

Die Warnungen und Fehler der Überprüfung werden in ... has no ..., so ... will not work und ...: the environment was entered, but ... is missing erklärt. Die Check Schaltfläche des Profils auf der Configuration Registerkarte meldet dasselbe für die Programme die Profilnamen.

Der Installationsassistent verfügt über drei intuitive Registerkarten, in denen die Benutzer ihre Entscheidungen nach ihren Bedürfnissen treffen:

  1. Settings: Installationsordner und Installationsprogramm Auswahl. Jeder Ordner und jede Datei wird in einem Dialog ausgewählt, so dass nichts eingegeben werden muss. Details zu softwarespezifischen Einstellungen finden Sie unten auf dieser Seite.

  2. Check: aXqua untersucht den Computer und listet die Befehle auf, die er ausführen wird, die erwartete Dauer und alles, was nicht in Ordnung ist. Ein orangefarbenes Dreieck markiert eine Warnung, mit der das Installation gestartet werden kann. Ein dunkelrotes Dreieck markiert einen Fehler. Um mit Installation fortzufahren:

    • Führen Sie aus, was das Feld unter REQUIRED USER ACTIONS in TERMINAL: verlangt.

    • Klicken Sie dann unten links auf Install.

  3. Installation: Führen Sie den aktuellen Schritt und das Ende des Installation-Protokolls aus. Der Installation ist ein eigener Prozess: Der Assistent und QGIS können geschlossen werden, während er läuft. Die Configuration Registerkarte meldet, dass ein Installation ausgeführt wird, und der Assistent zeigt es erneut an, wenn es wieder geöffnet wird.

Die Registerkarten können in beliebiger Reihenfolge besucht werden, und Back und Next am Ende des Assistent gehen durch sie hindurch. Geänderte Einstellungen werden erneut überprüft, wenn die Check Registerkarte geöffnet wird.

Am Ende überprüft aXqua, ob das Installationsprogramm das Programm erstellt hat, gibt das Programm und seinen Installationsordner in das Computerprofil (Plugin-Profil) ein und startet es einmal. Nach einem erfolgreichen Installation wird die Schaltfläche Cancel the installation dunkelgrau-grün und liest Installation complete; ein Klick schließt den Assistenten. Eine weitere Konfiguration ist nicht erforderlich.

In der Box Simulation & postprocessing software ist der Pfad eines gefundenen Programms in dunkelgrün und Not found on this computer. in fettem dunkellila geschrieben. Für ein Programm, das gefunden wurde, füllt das Setup Wizard sein Umgebungsskript aus und wählt Select existing config file aus. Wenn Sie Install <software-name> für ein bereits installiertes Programm auswählen, wird Software already installed. Continue with re-installation? No zuerst zur ConfigurationRegisterkarte zurückgegeben. Yes öffnet den Assistenten, dessen Settings Registerkarte dann mit der Einstellung beginnt Existing installation:

  • Remove the existing installation and install it again in its folder löscht den früheren Installation, bevor der neue erstellt wird. aXqua entfernt nur einen Installation, den einer seiner Installationsprogramme gemacht hat: den Unterordner telemac-mascaret von TELEMAC, einen Ordner des OpenFOAM Installationsprogramm oder die VisIt-Ordner der Postprozessoren.

  • Continue in the existing folder behält, was heruntergeladen und gebaut wird, und wiederholt die verbleibenden Schritte. Das OpenFOAM Installationsprogramm weigert sich, einen Ordner fortzusetzen, den eine andere Version gestartet hat; die Check Registerkarte sagt dies, bevor etwas läuft.

  • Install it again in a new folder lässt das bestehende Installation unberührt.

Bemerkung

Der Assistent führt Installationsprogramm-Skripte des Installationsprogramm-Repository aus, in der Version, mit der diese Version von aXqua getestet wurde. Das OpenFOAM Installationsprogramm dieses Repositorys wird zusammen mit dem Quellcode von Olsens Sediment Solver mit aXqua ausgeliefert, so dass die Installation von OpenFOAM nicht von der Website abhängt, auf der Nils Reidar Olsen sie veröffentlicht (das Repo war mit dem Fehler HTTP 502 im Oktober 2026 nicht erreichbar). Die Skripte existieren für Debian 12, Ubuntu 22.04, Ubuntu 24.04 und Linux Mint 22. Für ein anderes System, das auf einem dieser Systeme aufgebaut ist, wählen Sie das Basissystem unter Further settings auf der Settings Registerkarte.

Nutzerrechte

Systempakete und Administratorrechte: Compiler und numerische Bibliotheken sind Pakete des Betriebssystems, und ihre Installation ist der einzige Schritt, der Administratorrechte erfordert. Die Check Registerkarte gibt an, wie viele der erforderlichen Pakete fehlen, und zeigt den einen Befehl an, der sie in einem Feld unter der Überschrift REQUIRED USER ACTIONS in TERMINAL: installiert, beide in Dunkellila. Der Befehl kann auf zwei Arten ausgeführt werden:

  • Run fixes führt den Befehl aus. Auf einem Desktop fragt der Passwortdialog des Desktops nach dem Passwort; andernfalls öffnet sich ein Terminal Fenster und fragt danach. Das Passwort geht nicht durch das Plugin. aXqua überprüft dann den Computer erneut und wiederholt die Korrekturen, solange sie Fortschritte machen.

  • Copy the command Platziert den Befehl in der Zwischenablage, um in ein Terminal eingefügt zu werden. Senden Sie auf einem Computer, der von einer Institution verwaltet wird, den Befehl an den Administrator.

Wenn die Korrekturen das Problem nicht lösen, weil zum Beispiel die gleichen Pakete fehlen, erscheint die Schaltfläche Report issue. Es öffnet ein Fenster mit einem Bericht des Computers, dem Befehl und dem, was die Prüfung gefunden hat, in dem Ihr Home-Ordner als ~ geschrieben ist. Der Bericht kann gelesen und geändert werden, bevor er gesendet wird: Open on GitHub öffnet ein neues Problem im Issue Tracker (ein kostenloser GitHub-Account ist erforderlich), Send by e-mail öffnet das Mailprogramm mit dem Bericht (kein Account ist erforderlich) und Copy report platziert es in der Zwischenablage. Ein fehlgeschlagenes Installation bietet die gleiche Schaltfläche auf der Installation Registerkarte, mit dem Ende des Installation Logs im Bericht.

Nur für mich oder für alle Benutzer: Die erste Einstellung jedes Assistents, Install for, entscheidet, wer das Programm nutzen kann:

  • Me only (der Standard) wird in einem Ordner in Ihrem Home-Ordner installiert: ~/opt für TELEMAC, ~/.local/openfoam-sediment-v2406 für OpenFOAM und ~/.local/axqua-postprocessors für VisIt. Der Installation selbst erfordert keine Administratorrechte; nur fehlende Systempakete tun dies, wie oben beschrieben.

  • All users of this computer Installiert in einen Ordner unter /opt: /opt/telemac, /opt/openfoam-sediment-v2406 oder /opt/axqua-postprocessors. Der Build läuft weiterhin unter Ihrem Benutzerkonto, da sich Installationsprogramme weigert, als Administrator zu kompilieren. Das Passwort eines Administrators wird zweimal gefragt: vor dem Build, um den Ordner für Sie zu erstellen, und am Ende, um den Ordner an den Administrator zu übergeben, lesbar für jeden Benutzer und beschreibbar für niemanden sonst. Der aXqua jedes anderen Benutzers findet die Programme in diesen Ordnern ohne Eintrag in seinem Profil. Das spätere Ändern des Ordners, zum Beispiel um das Beispiel Fälle von TELEMAC hinzuzufügen, erfordert wiederum einen Administrator.

Auf dem Desktop fragt der Passwortdialog des Desktops nach dem Passwort. In einem Terminal lässt axqua install start openfoam --for-all-users --foreground sudo danach fragen; ein losgelöstes Installation ohne Desktop kann nicht fragen und stoppt, bevor es etwas erstellt.

Klicken Sie Check again danach. Der Installation selbst läuft mit den Rechten des gewöhnlichen Benutzers und schreibt nur in den Installationsordner.

Von einem Terminal Jeder Assistent entspricht einem Befehl, axqua install, der dasselbe ohne QGIS tut (Terminalsyntax).

TELEMAC

TELEMAC Löst die tiefengemittelten (2D) und 3D-Flüsse in Verbindung mit einer Vielzahl von Modulen für Zwecke wie Sedimenttransport (Gaia), Wasserqualitätsanalyse (WAQTEL), Wellenausbreitung (ARTEMIS und TOMAWAC). Sein Sedimenttransportmodul GAIA ist Teil desselben Installation. aXqua wurde mit TELEMAC v9.1.1 entwickelt und getestet.

Klicken Sie auf Setup Wizard… in der Reihe von TELEMAC auf der Configuration Registerkarte und wählen Sie Install TELEMAC. Der Installationsassistent ist unter Debian 12, Ubuntu 24.04 und Linux Mint 22 sowie unter Windows (TELEMAC basiert auf Windows) verfügbar. Auf Linux, seine Settings Registerkarte hat vier weitere Einstellungen Install for:

Einstellung

Bedeutung

Installation folder

TELEMAC ist im Unterordner telemac-mascaret dieses Ordners installiert. Der Standard ist der Ordner opt im Home-Ordner. Wenn der Unterordner bereits vorhanden ist, behält das Installationsprogramm seinen Quellcode und baut TELEMAC wieder darin auf.

TELEMAC version

Lassen Sie das Feld für v9.1.1 leer.

Example cases of TELEMAC

TELEMAC wird mit etwa 830 Beispielfällen verteilt. Ihre Steuerdateien werden immer mit dem Quellcode installiert. Die Einstellung wählt aus, wie viele ihrer großen Dateien zusätzlich heruntergeladen werden. Input files of examples only (der Standard) lädt herunter, was ein Beispiel liest, was hauptsächlich das Rechennetz ist: etwa 360 Dateien und 460 MB. Everything lädt auch die Referenzergebnisse herunter, mit denen sich TELEMAC selbst validiert, und die Handbücher: 1.500 Dateien und 1,65 GB, was etwa eine Stunde dauert. Steering files only lädt keine der großen Beispieldateien herunter. aXqua selbst benötigt keine dieser Dateien.

SALOME archive

Fakultativ Ein heruntergeladenes Archiv von SALOME, das dann neben TELEMAC installiert wird. aXqua verwendet Gmsh (Geuzaine und Remacle 2009) und benötigt SALOME nicht, da es das Rechennetz und die Eingabedateien selbst generiert.

Der Installation lädt den Quellcode von TELEMAC herunter und kompiliert ihn zur parallelen Berechnung mit den Systembibliotheken MPI, MUMPS, METIS und MED. Es erfordert etwa 2,5 GB freien Speicherplatz mit den Eingabedateien des Beispiels Fälle und etwa 5 GB mit allem. Auf einer Workstation mit 32 Prozessorkernen dauerte die Installation mit der Standardeinstellung 11 Minuten, wovon die Eingabedateien des Beispielfalls 7 Minuten dauerten.

Die großen Dateien des Beispiels Fälle werden getrennt vom Quellcode gespeichert, und der Download-Server liefert sie einzeln, wenn alle angefordert werden. Aus diesem Grund fordert die Standardeinstellung nur die Dateien an, die ein Lauf liest. aXqua bestimmt diese Dateien von TELEMAC selbst: Die Keyword-Wörterbücher von TELEMAC geben für jede Datei an, ob ein Lauf sie liest oder schreibt. Die fehlenden Dateien können jederzeit danach heruntergeladen werden: axqua install telemac-examples <folder> lädt die noch fehlenden Eingabedateien herunter, und git lfs pull im Ordner telemac-mascaret lädt alles herunter.

Das Ergebnis ist die Datei telemac-mascaret/configs/pysource.<system>.sh im Installationsordner. Diese Datei ist das Umgebungsskript von TELEMAC: Sie legt alle Variablen fest, die TELEMAC benötigt. Der Assistent gibt es als Solver Bindung von TELEMAC (Definieren Sie Solver Bindungen) in das Profil ein.

Wenn Installation fehlschlägt, zeigt der Assistent die letzten Zeilen des Installation-Logs und den Speicherort des vollständigen Logs an. Nachdem die Ursache behoben ist, starten Sie den Assistenten erneut mit dem gleichen Ordner. Das Installationsprogramm fährt mit dem fort, was bereits heruntergeladen wurde.

Ein Handbuch Installation wird im TELEMAC Installation tutorial beschrieben.

Verwenden Sie eine bestehende Installation von TELEMAC. Klicken Sie auf Setup Wizard… in der Zeile von TELEMAC, wählen Sie Select existing config file und klicken Sie auf Next. Wählen Sie das Umgebungsskript des Installation, das sich im Ordner configs von TELEMAC befindet und dessen Name mit pysource. beginnt und mit .sh:

<installation folder>/telemac-mascaret/configs/pysource.<configuration>.sh

Zum Beispiel /opt/telemac/telemac-mascaret/configs/pysource.debian12.sh. Ein TELEMAC Installation hat ein solches Skript pro Konfiguration seines Builds; Wählen Sie dasjenige des Builds aus, den Sie verwenden. Eine Datei, deren Name template enthält, ist ein Beispiel und richtet nichts ein. Die Überprüfung sucht nach TELEMAC-2D, die jede Simulation benötigt, und für TELEMAC-3D (3D-Simulationen und die vertikale Konvergenzstudie), GAIA (Morphodynamik, auch im Hydrologiemodus), Parallelläufe (partel und ein MPI-Launcher) und den Fortran-Compiler des Builds (Benutzer Fortran, der die Green-Ampt-Infiltration des Hydrologiemodus und der Gain-Lose-Austausch kompiliert). Das gleiche Skript kann per Hand im Profil-Editor (Definieren Sie Solver Bindungen) eingegeben werden.

TELEMAC auf Windows gebaut, ohne WSL. Auf einem Windows-Computer, auf dem WSL nicht eingerichtet werden kann, z. B. ohne Administratorrechte, kompiliert Setup Wizard TELEMAC als Windows-Programm in Ihrem Benutzerordner. Nichts davon braucht Administratorrechte. Der resultierende TELEMAC verfügt über kein Parallel-Computing (kein MPI) und führt jede Simulation auf einem Prozessorkern aus. Unter Windows 11 ohne Administratorrechte baute der Assistent TELEMAC v9.1.1 mit TELEMAC-2D in 16 Minuten, und ein Build mit den gleichen Befehlen lief die stationäre Simulation des Isar-Beispiels Fall in 58 Minuten auf einem Kern zu Ende. Nur TELEMAC-2D wurde getestet. TELEMAC-3D, Morphodynamik mit GAIA, der Hydrologiemodus und die Kalibrierung mit HydroBayesCal wurden unter Windows noch nicht getestet.

Klicken Sie auf Setup Wizard… in der Reihe von TELEMAC auf der Configuration Registerkarte und wählen Sie Install TELEMAC. Wenn aXqua bereits einen TELEMAC auf diesem Computer kennt, fragt er, ob er ihn erneut installieren soll: Antworte Yes und behalte Install it again in a new folder auf der SettingsRegisterkarte, um den bestehenden TELEMAC so zu belassen, wie er ist. Unter Windows hat die SettingsRegisterkarte dann die Einstellung Build TELEMAC:

  • In Windows itself: one processor core, no administrator ist die einzige Wahl auf einem Computer ohne WSL.

  • Inside WSL: parallel runs; WSL must be set up by an administrator wird angeboten, wenn WSL eingerichtet ist, und ist dann der Standard (siehe den Hinweis oben auf dieser Seite).

In Windows selbst eingebaut, hat TELEMAC diese Einstellungen:

Einstellung

Bedeutung

Installation folder

Der Standard ist opt\telemac in Ihrem Benutzerordner und ein neuer Ordner neben dem vorhandenen, wenn TELEMAC erneut installiert wird. Der Quellcode und der Build gehen in seinen Unterordner telemac-mascaret, die Compiler in seinen Unterordner telemac-build. Der Pfad darf keine Räume enthalten.

Modules

TELEMAC-2D with GAIA (Standard) ist der Build, der unter Windows getestet wurde. All modules, also TELEMAC-3D dauert länger und wurde noch nicht unter Windows getestet.

TELEMAC version

Lassen Sie das Feld für v9.1.1 leer.

In einem neuen Ordner listet die CheckRegisterkarte fünf Schritte auf:

  1. Download the compilers (conda-forge): eine Conda-Umgebung mit den GNU-Compilern für Windows (MinGW-w64), CMake, Make und Git, ein Download von mehreren hundert MB. Es wird mit der Conda des Installation erstellt, von dem aXqua aus läuft, daher muss aXqua für diese Route in einer Conda-Umgebung (Miniforge, Miniconda oder Anaconda) installiert werden, wie QGIS Plugin beschreibt.

  2. Download the source code of TELEMAC mit Git, ohne die großen Dateien von TELEMACs eigenem Beispiel Fälle.

  3. Configure the build mit CMake und MinGW Makefiles, ohne MPI, MED und MUMPS.

  4. Compile TELEMACTELEMAC-2D dauerte 10 Minuten mit 8 Prozessen auf dem Testcomputer.

  5. Write the environment script telemac-mascaret\configs\pysource.win.batEs legt nur Variablen fest und ändert nichts am Computer. aXqua gibt es dann in das Profil ein, wie am Ende jedes Installation, es sei denn, Enter the installation in the profile of this computer wird gelöscht (--no-bind in einem Terminal). Die Configuration Registerkarte zeigt es dann in der Reihe von TELEMAC an.

Der Installation geht weiter, wenn der Assistent oder QGIS geschlossen ist. Nachdem QGIS wieder geöffnet wurde, liest die Schaltfläche in der Reihe von TELEMAC Show the installation… und öffnet den Assistenten auf seiner InstallationRegisterkarte. In einem Terminal zeigt axqua install status telemac --tail 20 den Schritt und die letzten Zeilen des Protokolls. Das Protokoll install.log in %LOCALAPPDATA%\axqua\installs\<installation> gibt den Beginn und die Dauer jedes Schritts an.

Wenn der Server von TELEMAC nicht antwortet (er hat den Fehler HTTP 504 am 9. November 2026 zurückgegeben), stoppt der Installation im zweiten Schritt. Beginnen Sie es später erneut mit dem gleichen Installation folder: Der Plan hat dann weniger Schritte, da die Compiler beibehalten werden und ein Quellcode, der vollständig heruntergeladen wurde, ebenfalls beibehalten wird. In einem Terminal (der Anaconda Prompt oder Miniforge Prompt) tut axqua install start telemac --native dasselbe wie der Assistent; Geben Sie ihm den Ordner des ersten Versuchs mit --folder.

aXqua führt die Python-Scripts von TELEMAC mit dem Python der aXqua-Umgebung aus. Die Überprüfung des Profils meldet, dass Parallelläufe nicht verfügbar sind. Ein Job läuft dann auf einem Kern: Eine Anzahl von Prozessen, die aus dem Fall oder dem Computerprofil stammen, wird zu 1, mit einer Warnung in der Nachrichtenleiste von QGIS und oben im Protokoll des Jobs. Eine Zahl über 1, die mit dem Job angefordert wird (MPI processes im Plugin, --np in einem Terminal), wird vor Beginn des Jobs abgelehnt, da TELEMAC mit dem Fehler Parallel inconsistency aufhören würde. Das Abbrechen eines Jobs beendet TELEMAC und jeden Prozess, den es gestartet hat. Ein TELEMAC, das von Hand auf Windows aufgebaut ist, wird mit Select existing config file und seinem configs\pysource.<configuration>.bat eingegeben.

OpenFOAM

OpenFOAM ermöglicht eine bessere Strömungsauflösung in 3D, was besonders für die Simulation von Wasserbauwerken wie Wehren oder vertikalen Schlitzen wichtig ist. aXqua ist so konzipiert, dass es mit OpenFOAM v2406 funktioniert, wie es von OpenCFD (openfoam.com) vertrieben wird, was mit dem Sedimenttransport Solver sediDriftFoam (Olsen et al. 2023) und sediDriftFoam2 (Olsen 2025) kompatibel ist. Die Veröffentlichungen der OpenFOAM Foundation (openfoam.org) verwenden unterschiedliche Dateiformate und lesen nicht die Eingabedateien, die aXqua schreibt.

Wichtig

Installieren Sie TELEMAC auch, wenn OpenFOAM der Code of Interest ist. aXqua startet jede OpenFOAM-Simulation aus dem Ergebnis eines kurzen TELEMAC-Laufs, der als Warm-up (aXqua Warm-up Konzept) bezeichnet wird. Ohne sie muss OpenFOAM eine trockene Flusssohle alleine mit Wasser füllen, was die Rechenzeit vervielfacht.

Klicken Sie auf Setup Wizard… in der Reihe von OpenFOAM auf der Configuration Registerkarte und wählen Sie Install OpenFOAM. Der Installationsassistent ist auf Debian 12, Ubuntu 22.04, Ubuntu 24.04 und Linux Mint 22 auf Computern mit einem x86-64-Prozessor verfügbar. Es installiert die folgenden Komponenten in einem Ordner:

  • OpenFOAM v2406, es sei denn, ein Installation dieser Version existiert bereits (siehe die Einstellungen unten).

  • Der Sedimenttransport Solver sediDriftFoam (Olsen et al. 2023) und sediDriftFoam2 (Olsen 2025), und eine Variante des letzteren mit einer Ausfluss mit Abflusskurve, sediDriftFoam2Rating, die das Installationsprogramm als nicht validiert kennzeichnet.

  • Die Ausflussrand mit Abflusskurve des Federal Waterways Engineering and Research Institute (BAW) für Solver interFoam (Thorenz 2024).

  • Die Postprozessoren ParaView und VisIt (Postprozessoren), sofern sie nicht deselektiert sind.

Fügt das Beispiel Fall hinzu, das mit sediDriftFoam veröffentlicht wurde.

Run a short test at the end

Läuft interFoam für einige Zeitschritte mit dem Ausflussrand der BAW, der überprüft, dass die kompilierte Bibliothek geladen werden kann.

Ein verpacktes OpenFOAM v2406 spart die Stunden der Zusammenstellung. OpenCFD bietet Pakete für Debian und Ubuntu. Ein Administrator installiert sie gemäß Installation Anweisungen von OpenCFD, der die Datei /usr/lib/openfoam/openfoam2406/etc/bashrc erstellt. Der Assistent findet das Installation von selbst.

Das Ergebnis ist die Datei shell-rc.sh im Installationsordner. Es ist das Umgebungsskript dieses Installation: Es lädt OpenFOAM v2406 und fügt den kompilierten Solver und die Rand-Bibliothek hinzu. Der Assistent gibt sie als Solver Bindung von OpenFOAM in das Profil ein und gibt die ausgewählten Postprozessoren ein. Es werden keine bestehenden OpenFOAM Installation und keine Startdatei des Benutzerkontos geändert.

Verwenden Sie eine bestehende Installation von OpenFOAM. Klicken Sie auf Setup Wizard… in der Zeile von OpenFOAM, wählen Sie Select existing config file und klicken Sie auf Next. Wählen Sie eines von zwei Umgebungsskripten:

  • <installation folder>/shell-rc.sh eines OpenFOAM Installation, das der Assistent erstellt hat, zum Beispiel ~/.local/openfoam-sediment-v2406/shell-rc.sh. Dies ist die empfohlene Wahl, da es auch das Sediment Solver und den Ausflussrand der BAW einrichtet.

  • <OpenFOAM folder>/etc/bashrc einer OpenFOAM v2406, eine Datei ohne Ende, zum Beispiel /usr/lib/openfoam/openfoam2406/etc/bashrc des Pakets von OpenCFD.

Der Check sucht nach dem Solver, den jede aXqua-Simulation verwendet (interFoam, checkMesh, decomposePar, reconstructPar), und nach dem Release v2406, Olsens sediDriftFoam2 (die Feinsediment-Simulation) und dem Ausflussrand mit Abflusskurve der BAW (ein Ausfluss auf einem Abflusskurve). Ein OpenFOAM ohne Sediment Solver oder einer anderen Version wird als gültig mit den Modulen gemeldet, die nicht funktionieren: Die freie Oberfläche Simulationen laufen damit. Um das Sediment Solver zu einer OpenFOAM v2406 hinzuzufügen, wählen Sie Install OpenFOAM und Use the OpenFOAM v2406 that is installed on this computer, die nur die Solver und die Rand Bibliothek kompiliert.

Bemerkung

aXqua erstellt Simulationen mit dem Sedimenttransport Solver sediDriftFoam2, für Feinsediment über einem Bett, das an Ort und Stelle bleibt (Simulations > Morphodynamics mit dem Simulationsprogramm OpenFOAM, OpenFOAM Setup), und OpenFOAM-Simulationen mit der Ausflussrand mit Abflusskurve der BAW (openfoam.outflow_boundary: rating-curve, OpenFOAM-Auswahl). Die Variante sediDriftFoam2Rating, die das Bett und den Wasserspiegel bewegt, wird von aXqua installiert, aber nicht eingerichtet, da aXqua das Bett und die Oberfläche einer Sedimentsimulation an Ort und Stelle hält.
